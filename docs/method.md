# 方法说明

## 从示范学习到在线优化

SFT 解决“如何按照协议使用工具”：基于完整交互轨迹学习调用格式、反馈利用与作答。RL 解决“当前状态下如何选择后续行为”：从当前策略在线采样，通过完成轨迹的相对奖励更新策略。

两阶段均使用 LoRA。RL 从选定 SFT 模型初始化新的适配器；关闭该适配器时得到固定 SFT 参考策略，用于 KL 约束。优化器、优势计算与 DR-GRPO 损失由 TRL 提供。

## 数据流程

公开问题来自 GSM8K、MATH、HotpotQA 的训练分区，另构建文档内检索计算任务。先按问题去重、文档隔离与合成世界分组划分题池，再构造示范。

| 环节 | 处理方式 |
| --- | --- |
| 公开示范 | Tool-Star 原问题与 SFT 题池精确归一化匹配；过滤重叠、格式及答案不合格样本；Python 轨迹重放并核对返回值 |
| 生成轨迹 | 对未覆盖问题先生成 2 条，均未通过才追加 2 条；选择首条合法且答案正确的轨迹，不按调用次数筛选 |
| SFT 标签 | 模型 token 参与监督；system、user、工具返回及模板附加片段的标签为 `-100` |
| 开发与测试 | 开发集用于配置和检查点选择，冻结后再执行最终测试 |

公开示范含直接作答样本，不要求每条都调用工具。最终样本数为 2,817 + 3,429 = 6,246。SFT 原始题池包含 8,000 题；通过率筛选后未将失败样本补齐或复制。

## 正确性门控的调用成本

对同一题的候选组，令 $a_i$ 为答案是否正确，$c_i$ 为逻辑工具调用次数，$u_i$ 为无效调用次数；$c_{\min}$ 是同组正确轨迹的最少调用次数，调用上限 $C=5$：

$$
r_i=a_i-\mu\min(u_i/C,1)-\lambda_t a_i\min\left(\max\left((c_i-c_{\min})/C,0\right),1\right)
$$

若同组没有正确轨迹，则不计算成本项。无效调用惩罚系数 $\mu=0.02$；成本系数在前 20% 更新中为 0，随后线性增加至 0.1。

这样，少调用但答错不会获得成本优势；答对的候选之间才进一步比较额外调用。奖励进入 TRL 后采用组内中心化优势，不除以组内奖励标准差。实现见 [rewards.py](../src/tooltune/rewards.py)。

## 熵引导分支采样

采样分布使用温度缩放后的全词表概率，单位置熵为：

$$H_t=-\sum_{v\in V}p_t(v)\log p_t(v)$$

1. 先完成每题 2 条根轨迹，记录工具反馈节点。
2. 对每个节点，计算反馈后最多 16 个模型 token 的平均熵，减去发起该次调用的动作开头最多 16 个模型 token 的平均熵。
3. 将熵差映射为历史经验分位数，达到中位数阈值的节点进入候选，按分数选择最多 2 个分支。
4. 拷贝截至工具反馈的前缀，以新采样种子生成后续轨迹；分支不足时补充独立根轨迹。
5. 候选按题连续组成 4 条完整轨迹，统一计算奖励和策略损失；完成本批后更新熵历史。

全局方案共享历史统计；工具条件方案区分 Python / search，某工具历史不足 32 个点时回退至全局统计。熵是探索信号，不是正确性分数，也不直接加到奖励中。

这里保持的是**每题候选数**。分支会共享前缀，但熵计算和新续写仍有开销，不能将该设计直接等同于固定生成 token 数或固定训练耗时。

### 消融配置

| 配置 | 成本项 | 采样 |
| --- | --- | --- |
| G0 | 无 | 4 条独立轨迹 |
| G1 | 有 | 4 条独立轨迹 |
| G2 | 有 | 随机分支 |
| G3 | 有 | 全局熵分支 |
| G4 | 有 | 工具条件熵分支 |

G2–G4 均预留 2 个分支名额。共享前缀在每条候选的损失中保留，逻辑调用次数也包含该前缀；实际新增执行次数单独计数。环境 token 的掩码为 0，模型 token 的掩码为 1。

## 训练与推理的衔接

`Rollout.sample()` 返回候选 token、采样 logprob、环境掩码和奖励所需记录。vLLM 在一批采样前同步当前策略；采样结束后，TRL 使用 DR-GRPO 损失更新 LoRA 参数。SFT 参考权重固定，KL 系数为 0.01。

训练采样温度为 0.8；最终评测使用贪心单轨迹解码。测试指标在直接作答、数学计算、多跳问答与检索计算四类任务上分别计算，再作宏平均。
